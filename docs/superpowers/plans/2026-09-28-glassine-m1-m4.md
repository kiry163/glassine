# glassine (M1–M4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `glassine`, a Windows desktop transparent overlay that shows the current time by default and accepts caller-supplied text over a localhost HTTP API.

**Architecture:** One crate, one process, two threads. The window thread owns a `WS_EX_LAYERED` popup and does all rendering by compositing glyph coverage into a top-down 32bpp DIB and presenting it with `UpdateLayeredWindow`. An HTTP accept thread parses requests, pushes `Command` values into an `mpsc` channel, and wakes the window thread. Every module except `platform` is platform-free and therefore headlessly unit-testable.

**Tech Stack:** Rust (edition 2021), `windows` 0.62, `cosmic-text` 0.19, `toml` + `serde` + `serde_json`, `log` + `time`, no async runtime.

**Spec:** `docs/superpowers/specs/2026-09-28-glassine-design.md` — read it alongside this plan. Every value below is copied from it.

## Global Constraints

- Target: Windows 10 1809+, x86_64-pc-windows-msvc. Process declares Per-Monitor V2 DPI awareness. All coordinates and sizes are **physical pixels**.
- Single crate, no workspace. No `tiny-skia`. No async runtime.
- **Every module except `platform::*` must not reference the `windows` crate.** This is what makes the core testable and the macOS port a rewrite of `platform` only.
- **`SetLayeredWindowAttributes` must never appear in the code.** One call permanently breaks `UpdateLayeredWindow` on that window with `ERROR_INVALID_PARAMETER (0x80070057)`.
- Window: `WS_POPUP` + `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOPMOST` (exstyle `0x080800A8`, `WS_EX_APPWINDOW` unset). Built as a GUI-subsystem app (`#![windows_subsystem = "windows"]`).
- Composition order is fixed: fill transparent → premultiply coverage → source-over → swap R/B → present.
- HTTP binds `127.0.0.1` only, default port `17321`, never `0.0.0.0`. No authentication. Body limit `65536` bytes. Socket read/write timeout `2 s`.
- Exit codes: `0` ok, `1` instance already running, `2` invalid config, `3` port in use.
- Paths: config `%APPDATA%\glassine\config.toml`; position override `%LOCALAPPDATA%\glassine\window_state.json`; logs `%LOCALAPPDATA%\glassine\logs\glassine.log` (1 MiB × 3 rotation). Config is read **only at startup** and is never rewritten by the program.
- Single-instance mutex `Glassine.SingleInstance`. Window thread wake message `WM_APP + 1`. Tray uses a hidden message window, never the main window.
- Error responses reuse the success envelope: `{"ok":false,"error":{"code":"...","message":"..."}}`.
- Panic hook logs, then `abort`.
- Resource ceilings (measured on the spike, see spec §14): working set ≤ 15 MB, private ≤ 5 MB, idle CPU ≤ 0.5% of one core, first frame ≤ 50 ms, frame p95 ≤ 1 ms, exe ≤ 5 MB, steady threads ≤ 4, steady handles ≤ 200.

- [ ] **Step 3: Implement `src/config.rs`**

Serde structs mirror the spec's TOML exactly (`[window]`, `[text]`, `[clock]`, `[server]`, `[log]`). Parse into a `Raw*` mirror of `Option` fields, then validate into `Config` so that (a) missing keys take defaults and (b) every rejection produces `ConfigError { field, message }` with the dotted field path shown in the tests. Validation lives in one `validate(...) -> Result<Config, ConfigError>` function so ordering is explicit; `UtcOffset` accepts `"local"` or `^[+-]\d{2}:\d{2}$` with `|hours| ≤ 14`.

Resolution order is defaults < file < environment < command line. `GLASSINE_CONFIG` selects the file and is read before parsing; `GLASSINE_PORT` and `GLASSINE_LOG` are applied after, then `--config`, `--port`, `--log-level` win over everything. Environment values go through the same validators as file values, so `GLASSINE_PORT=loud` fails with field `server.port` (exit code 2), not a silent default.

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn rotation_keeps_three_files_and_drops_the_oldest() {
        let dir = std::env::temp_dir().join("glassine-plan-rotation");
        let _ = std::fs::remove_dir_all(&dir);
        std::fs::create_dir_all(&dir).unwrap();

        assert!(dir.join("glassine.log.2").exists());
```

Run: `cargo test logging`
Expected: FAIL — `cannot find type FileSink`.

- [ ] **Step 3: Implement `src/logging.rs`**

`MAX_LOG_BYTES = 1 << 20`, `KEEP_FILES = 3`. `FileSink` is a small `std::fs::File` wrapper with an explicit byte counter; when appending a line would exceed `MAX_LOG_BYTES` it rotates (`log.2`→`log.3` dropped, `log.1`→`log.2`, `log`→`log.1`) before writing. `init` installs a `log::Log` that writes `"<rfc3339> <LEVEL> <target> <message>"` and additionally mirrors `Warn`/`Error` to stderr so a console-launched run is readable. Use `std::sync::Mutex` around the sink; never block the caller longer than one write.

`init` also installs a panic hook (spec §11) that logs the panic message and source location at `error` **before** the process aborts. The release profile sets `panic = "abort"`, and the hook still runs first. Without it a panic in a GUI-subsystem build is invisible: there is no console, and the window simply disappears with no record of why.

- [ ] **Step 4: Implement `src/platform/win/mod.rs`**

Create the window with the exact style mask from Global Constraints and the `WindowClass` registered with a `wndproc` that dispatches to the `WindowEvents` handler stored in `GWLP_USERDATA`. Create the DIB with `biHeight = -(height as i32)` (top-down) so `stride == width * 4`. `present` builds `BLENDFUNCTION { BlendOp: AC_SRC_OVER, BlendFlags: 0, SourceConstantAlpha: 255, AlphaFormat: AC_SRC_ALPHA }` and calls `UpdateLayeredWindow` with `pptDst = (self.x, self.y)`.

Message handling:

| Message | Action |
|---|---|
| `WM_PAINT` | `BeginPaint` + `EndPaint` (mandatory; omitting them re-posts `WM_PAINT` forever and burns ~81% of a core) |
| `WM_ERASEBKGND` | return 1 |
| `WM_TIMER` (id `TIMER_TICK`) | `handler.on_tick()` |
| `WM_APP + 1` | `handler.on_command(...)` until the channel drains (the channel lives in `App`, not here) |
| `WM_DPICHANGED` | update the cached DPI, `handler.on_dpi_changed(dpi)` |
| `WM_DISPLAYCHANGE` | `handler.on_display_change()` |
| `WM_SETCURSOR` | while in move mode set `IDC_SIZEALL`, otherwise `DefWindowProc` |
| `WM_LBUTTONDOWN` / `WM_MOUSEMOVE` / `WM_LBUTTONUP` | move mode only — implemented in Task 13 |
| `WM_CLOSE` / `WM_DESTROY` | `PostQuitMessage(0)` |

`run_message_loop` uses `GetMessageW` + `TranslateMessage` + `DispatchMessageW`. `destroy` calls `DestroyWindow`, then deletes the bitmap, the memory DC and releases the screen DC.

`set_position` **must both** call `SetWindowPos(..., SWP_NOSIZE|SWP_NOZORDER|SWP_NOACTIVATE)` **and** update the cached `self.x`/`self.y` that `present` uses as `pptDst`. Skipping the second half makes the next redraw yank the window back to the old position.

**Topmost re-assert (spec §6.5).** `WM_TIMER` id `TIMER_REASSERT` fires every `window.reassert_topmost_ms` (0 disables it). `reassert_topmost` reads `GWL_EXSTYLE`; when `WS_EX_TOPMOST` is missing it calls `SetWindowPos(HWND_TOPMOST, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)` and logs at `info`. It **must not** touch the surface or trigger a redraw: this timer runs every 5 s for the life of the process, and a redraw here would break the idle-CPU ceiling in spec §14.

```rust
use std::io::{Read, Write};
use std::net::TcpStream;
use std::process::{Child, Command};
use std::time::{Duration, Instant};

struct Harness { child: Child, port: u16 }

impl Harness {
    fn start(port: u16) -> Self {
        let dir = std::env::temp_dir().join("glassine-plan-http");
        std::fs::create_dir_all(&dir).unwrap();
        let config = dir.join("config.toml");
        std::fs::write(&config, format!("[server]\nport = {port}\n[window]\nsize = [320, 120]\n")).unwrap();

        let child = Command::new(env!("CARGO_BIN_EXE_glassine"))
            .arg("--config").arg(&config)
            .spawn()
            .unwrap();
        let h = Harness { child, port };
        h.wait_until_listening();
        h
    }

    fn wait_until_listening(&self) {
        let deadline = Instant::now() + Duration::from_secs(10);
        while Instant::now() < deadline {
            if TcpStream::connect(("127.0.0.1", self.port)).is_ok() { return; }
            std::thread::sleep(Duration::from_millis(50));
        }
        panic!("server never accepted a connection on port {}", self.port);
    }

    fn request(&self, raw: &str) -> String {
        let mut s = TcpStream::connect(("127.0.0.1", self.port)).unwrap();
        s.set_read_timeout(Some(Duration::from_secs(5))).unwrap();
        s.write_all(raw.as_bytes()).unwrap();
        let mut out = String::new();
        let _ = s.read_to_string(&mut out);
        out
    }
}

impl Drop for Harness {
    fn drop(&mut self) { let _ = self.child.kill(); let _ = self.child.wait(); }
}
```

- [ ] **Step 3: Implement the server and the wake-up path**

`Server::bind` uses `TcpListener::bind(("127.0.0.1", port))` and maps `ErrorKind::AddrInUse` to `BindError::InUse` (exit code 3 in `main`). `serve` runs a single accept thread: accept one connection, set 2 s read/write timeouts, read up to the header terminator plus `Content-Length`, parse, route, respond, close, repeat. The `HWND` crosses to the HTTP thread as an `isize` captured in the `wake` closure; no `windows` types leave `platform`.

## Review Focus

Five input classes and failure modes the spec implies or leaves silent, each pinned to a test in the task that owns the code:

1. **A text body at the 64 KiB limit.** `POST /text` with 60 000 CJK characters must truncate cleanly rather than panic, stall, or exhaust memory — Task 7 `a_sixty_kibibyte_text_shapes_without_panicking`, Task 10 `body_limit_is_inclusive_at_65536_and_rejected_at_65537`.
2. **A configured monitor that does not exist** (unplugged external display, `monitor = "1"` with one monitor). Spec §10.3 rejects malformed selectors but never says what an index that is syntactically valid but absent from the hardware should do. It must fall back to the primary monitor and `warn!`, never fail startup — otherwise an autostart entry breaks the moment a laptop is undocked. Pinned by Task 8 `a_monitor_that_is_not_attached_falls_back_to_primary_without_failing`, which also covers the empty monitor list.
3. **A viewport too short for even one line.** `size = [640, 10]` with 34 px text must render nothing and set `truncated`, not panic or index out of bounds — Task 7 `a_viewport_shorter_than_one_line_truncates_instead_of_panicking`.
4. **A degenerate clock format.** Empty and lone-`%` formats are rejected at startup rather than silently rendering an empty window — Task 2 `every_invalid_field_fails_and_names_itself`.
5. **A window larger than the monitor work area.** `size = [4000, 3000]` on a 1920×1080 desktop must still resolve, still present, and never wrap a `u32` subtraction into a huge coordinate — Task 1 `resolve_rect_allows_negative_positions_and_oversized_windows`, plus the same case presented through `--check-config` in Task 2.

Two spec gaps this section caught, both resolved during planning and written into the spec rather than left to the implementer:

- **§7.2 and §11 contradicted each other** on whether the tray has two or three items, because move mode was added to §7.2 after the tray had been fixed at two actions. Resolved in favour of **three items** — 移动窗口, 打开配置文件, 退出 — and §1, §3.9, §4, §7.2, §11 and §19 were updated to match.
- **§8.2 fixed horizontal alignment (`text.align`) but never said where the text sits vertically.** Resolved: **centred**. `TextEngine::shape` centres `rows * line_height` inside the viewport, which is the forgiving choice for a fixed-size overlay showing one or two lines.
